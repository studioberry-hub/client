## Как предложить изменения

1. Форкните репозиторий и создайте ветку от актуального `main`
   (`git fetch upstream && git checkout -b feature/... upstream/main`).
2. Внесите изменения, следуя [требованиям к коду](#требования-к-коду).
3. Убедитесь, что проект собирается: `npm run build` (или эквивалентная
   команда сборки, указанная в `package.json`).
4. Откройте Pull Request по шаблону ниже.

## Требования к коду

- Следуйте существующему стилю файлов, которые вы изменяете
  (TypeScript, структура `src/`).
- Не добавляйте комментарии без необходимости — код должен говорить сам
  за себя.
- Не изменяйте поведение запуска Minecraft и Modrinth-кеша без явного
  обсуждения в issue.
- Все зависимости добавляются через `npm`, лишние пакеты не приветствуются.
- Не включайте в коммиты приватные ключи, токены и пользовательские
  данные (логи, кеши, аккаунты).

## Порядок оформления PR

Каждый PR должен содержать:

- понятное название и описание изменений;
- ссылку на issue, если оно есть;
- сведения о тестировании (какие сценарии запуска проверены);
- по возможности — скриншот, если изменение касается интерфейса.

Стиль названий веток: `feature/`, `fix/`, `refactor/`, `docs/`.

Ветка PR должна быть актуализирована (rebase на последний `main`)
непосредственно перед открытием. Менеджер проекта вправе отклонить PR,
если изменения противоречат целям проекта или лицензионным условиям.

## Условие актуализации форков (ребазинг)

Это отдельное **договорное условие** участия в экосистеме проекта
(не часть лицензии, см. п. 4 аддендума в LICENSE):

1. Публичный форк, распространяющий производную версию, обязан в срок
   не более **30 календарных дней** с даты релиза оригинала привести
   свою ветку в соответствие с этим релизом (ребазинг, принятие
   критических исправлений и обновлений).
2. При систематическом невыполнении этого условия автор проекта вправе
   публично указать на несоответствие форка актуальной версии;
   участие в разработке проекта для такого форка может быть приостановлено.
3. Условие не распространяется на лиц, использующих Программу без
   распространения изменённых версий.
